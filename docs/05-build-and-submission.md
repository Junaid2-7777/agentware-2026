# Build plan and submission

Planning ends with a source and decision check; implementation is separate. All project code must be authored within the official window. Do not copy an inventory project or a prior agent.

| Order | Work block | Gate |
| --- | --- | --- |
| 1 | Fresh fixture, canonical schemas, local SQLite queue and baseline reconciliation | A complete shift is recognized; duplicates and incomplete feeds safe; actual rows persisted. |
| 2 | Bounded evidence agent, tool validation, replay and live adapter | Model choice changes a legitimate case on handoff evidence; unsupported proposal degrades safely. |
| 3 | Cancellation, trace, live status, reliability pass | No late writes after cancel; rerun idempotent; judge can trace two different decisions. |
| 4 | Cold start, comparison and honest limitations | Clean checkout; measured setup time; relevant Trap Pack observations and benign controls filled in. |
| 5 | Actual demo recording and release review | Public, OSI license, no secrets, install verified, one authentic unassisted run under 3 minutes. |

Budget suggestion for one builder: 4h for the vertical slice, 4h for agent and fallback, 4h for testing/cancellation, 3h for documentation/video; leave comfortable buffer around other weekend commitments. Plan to freeze locally by November 30 at 21:30 IST and submit by 22:30 IST, one hour before official 23:30 IST. These are targets, not calendar changes. If behind, cut UI chrome, hosted adapters, partner integrations, and unsupported input formats. Keep queue, evidence, visible stop, and reliable install.

## The smallest version worth submitting

Build one complete story before building a dashboard: an arrival-triggered receiver runs against synthetic files, an evidence lookup changes a legitimate exception, and one task is committed into a queue the judge can inspect. Show the same queue after a restart. Terminal status, a local stop action, and a human-readable trace are sufficient for the first cut; nobody should need a browser, database console, or service account to judge the core.

| First cut | Keep | Drop if behind |
| --- | --- | --- |
| Inputs | One schema, one workspace, one manifest-verified completed shift, UTC fixtures, explicit due quantity | ERP adapters, uploads UI, free-form unit conversions, multi-warehouse configuration |
| Decisions | One meaningful choice: conditional corroboration of a later shipment vs recount; incomplete batches isolated before model use | More agents, auto-close, vector search, model-selected thresholds |
| Outputs | SQLite queue, brief derived from saved rows, one readable event timeline | Stock updates, alerts, provider dashboards, charts, hosted integrations |
| Proof | Real unattended run, offline judge replay, benign controls, bounded stop, failure/retry evidence and a clean checkout | Multiple tracks, sponsor integration, interactive tour, extra scenario animation |

### Do not move on until each proof exists

1. **Local write:** Show the queue before and after one batch. Repeat it and confirm the same active task keys and counts. A printout is not a write.
2. **Agent contribution:** Keep trusted counts fixed. Change only corroborating evidence. Show that the live agent chooses a grounded lookup or falls back honestly, and that the resulting status differs from the generic baseline for at least one novel fixture. If not, tighten the evidence decision before adding screens.
3. **Stop:** Use the same writer in normal and slow-test modes. Stop while work is pending, allow any delayed response to return, and inspect a separate reader for zero new tasks. Preserve already committed rows and label that case correctly. Report measured stop-to-acknowledgment latency, not remote compute cessation.
4. **Clean setup:** Open a fresh checkout with no provider key; time from the first README command to a queue and trace. Keep replay usable even without a network. A recording is evidence of one run, not evidence that a judge reproduced model behavior.
5. **Recording:** Make one continuous, truly unattended trigger-to-commit demo before any optional material. If it runs long, shrink the fixture, not the evidence. The judge path can replay that trace; label live, replay and synthetic slow-test footage separately.

Prefer measured time-to-first-result and the concrete work-queue diff to a made-up productivity claim. The two-hour ideation phase establishes these gates; it does not establish that any have passed.

## Judge-ready files and checks

- Replace the root event guide with verified project run instructions; retain a rules recap under docs. Keep final project README brief: product, CLI, expected outputs, modes (live vs replay), required API tier if any, tested runtime and limitations.
- Add `LICENSE`, `AGENT.md`, `SAFETY.md`, `.env.example`, `src/`, `tests/`, `traces/`, and optionally `.agentware.toml` in the implementation phase. Track exact model names, allowed tools, real traces, limits and observed test results.
- Verify public repo and video links in a signed-out context. Confirm authentic run and clean install, license, all individual registrations, one track (Open), concise pitch and all exact form fields. Only the latest pre-freeze submission is judged. No submission in this planning phase.
- Optional: a Near Miss post about a real failure and fix, only if it happened and evidence is cleared to share. Skip all sponsor work until the core passes; optional perks are not a scoring shortcut.

## Final pre-build go/no-go

Proceed with DockCheck if the MVP still needs only one workspace, one dataset shape, one local persistent action, one evidence-dependent decision, and zero account dependency on the default judge path. If a design choice expands scope, defer it. Any real-world warehouse integration, spending, or notifications are explicitly out of scope.
